# 记忆机制

Mote 不存"消息数组"，存的是**追加式事件流**。每条会话一个 `events.jsonl`，
一行一个事件，只追加、不改写。这个决定换来了三件事：分支可以随便开、删除可以撤销式实现
（软删除）、崩溃最多丢最后一行。

## 存储布局

```
memory/
  sessions/
    s-20261123-1a2b/events.jsonl      # 一条会话的全部事件
  session_index.json                   # 会话摘要缓存（生成物，可删）
```

## 事件类型

| 类型 | 关键字段 | 作用 |
|---|---|---|
| `session` | `id` / `ts` | 会话创建 |
| `title` | `title` | 重命名（覆盖式，取最后一条） |
| `user` | `text` / `ts` / `node` / `parent` | 一次提问，同时定义树上的节点 |
| `assistant` | `text` / `ts` / `node` / `parent` / `model` / `route` / `thinking` / `stopped` | 一条回答 |
| `cursor` | `node` | 当前所在分支节点（幂等记录，可反复追加） |
| `main` | `node`（可为 `null`） | 主分支标记（覆盖式，`null` 取消） |
| `delete` | `node` | 软删除某个问答及其后续 |

**没有任何事件被物理删除。** 删除只是追加一条 `delete`，读的时候过滤掉；
所以删除可审计，也不会因为并发读而出现半截文件。

## 节点与分支

一次提问 + 它的一条回答 = 一个节点。节点用稳定的 `node` 标识，`parent` 指向上一节点。
于是同一段历史可以长成一棵树：

```
Q1 ─ A1 ─ Q2 ─ A2        ← 主链
            └─ Q2' ─ A2'  ← 同一问题的另一次回答（重新生成、编辑后重问）
```

- `parent` = X：新问题接在 X 之后，成为 X 的子节点。
- `fork` = X：新问题与 X **同级**，原分支完整保留。网页的「重新生成」和「编辑后重问」
  都走这条路，产生 `1/N` 序号里可切换的兄弟分支。
- `node` 事件始终显式写 `parent`（可以为 `null`），不能用"缺省就沿用上一个"来判断，
  否则根级兄弟分支会被错误串成子节点。

## cursor 与 main

这两个标记决定"打开会话时落在哪条链上"，都只是入口，不限制你去别处：

| 标记 | 何时写 | 谁优先 |
|---|---|---|
| `cursor` | 用户切换分支、跳转节点、导入时写入 `current_message_id` | 次要 |
| `main` | 用户点「···」→「设为主分支」 | **优先于 cursor** |

`_active_node` 先看有没有 `main`，没有再取最后一条 `cursor`；两者都只记录**分叉点**，
真正的落点会沿子节点走到该分支末端，所以切换后能看到这条分支自己的后续。

在主分支末端继续提问时，`user()` 会自动追加一条 `main` 事件把标记前移，
标记不会停在旧位置；删除命中主分支时写 `main: null`。

关键：`main` 只影响打开会话时的视图。`GET /messages|/tree`、`DELETE`、`POST /inbox`
都接受显式的当前视图（`?node=`、`?tip=`、`parent`），前端统一用"最后一条 user 节点的 node"，
所以跳出去不会被拽回主分支，在别的分支上提问也不会接到主分支去。

## 状态卡

`memory.state_card(chars)` 把当前链路压成一段短文本：标题、轮数、最近几轮的问题与回答摘要。
它是路由器看到的历史，也是本地直答的全部上下文，默认 1600 字。

状态卡只沿**当前路径**生成——切到别的分支，送进模型的上下文同步跟着变。

## 会话列表与索引

打开页面不重扫全部历史：

- `_known_session` 只 `stat` 文件，不解析；
- `list_sessions` 按 `mtime + size` 判断是否需要重新摘要，摘要写进
  `memory/session_index.json`，跨进程复用；未变的会话只 stat、不解析；
- `session_index.json` 删掉只会让下次列表慢一次，不影响正确性。

**列表时间是"最后一次提问"的时间**，不是文件 mtime。切分支、重命名、删除、设主分支、
导出都会追加事件，用 mtime 会把对话无端顶到最前——只有新问题才会改变排序。
索引里没有 `date` 字段的旧条目会自动重算。

实测约 160 个会话、36 MB 日志：冷启动列表约 0.2 秒，热启动约 20 毫秒；
单会话读取只走一次磁盘（消息流与分支树共用同一份事件快照）。

## 思考原文

思考原文存在 `assistant.thinking`，但**不下发到消息列表**：列表只带 `thinking_chars`，
展开折叠块时才 `GET /sessions/<id>/thinking/<node>` 取正文。这样 5000 字的推理不会
拖慢首屏，历史回填也不会把它塞进上下文。

一条节点可能有多次思考（工具轮），`thinking_for` 取最长的那段。

## 导出

- 当前分支 → Markdown：问题用引用块，回答保留原始 Markdown，思考折叠进 `<details>`，
  末尾标注本地/云端与模型名；`thinking=0` 可去掉思考。
- 当前会话 → JSON：带当前分支 `messages`、完整 `tree` 与逐节点 `branches`，可无损还原分支结构。
- 全部会话 → 单个 JSON 备份。
